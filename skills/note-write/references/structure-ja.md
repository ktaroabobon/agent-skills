# 一読で通る文にするための点検項目

この参照が扱うのは、文と段落の**構造**である。AI 臭や表記・語法 (SKILL.md の Step 7 が担当) とは別の層で、意味は正しく表記も揃っているのに一読で頭に入らない状態を対象にする。

読み返して引っかかったとき、原因はたいてい以下のどれかに当たる。「なんか読みづらい」で止めず、症状から原因を特定してから直す。症状だけ外しても読みにくさは残る。

## 当てる範囲

- **短いノート (H2 が 2 つ以下)** — §1.1 / §1.2 / §2.1 / §3.1 の 4 つだけ。実際の引っかかりの大半はこの 4 つで説明できる
- **長いノート、`00-index.md`、他人に出すブロック (メール返信案 / Slack 下書き) を含むノート** — 全項目

全項目を機械的に当てるのは時間の無駄なので、短いノートで 4 つを超えて当てない。

---

## 1. 語の一貫性

### 1.1 同じものを 2 つの名前で呼ばない

- **症状**: 既出の概念なのに、読者が新しい概念だと解釈して一瞬止まる
- **原因**: 言い換え。書き手は同語反復を避けたつもりでいる

実例:

| 先に出した語 | 後で呼び直した語 |
| --- | --- |
| 与えられた目的 | 仕事の目的 |
| 実行できる操作 | ツール |
| 停止条件 | 調査を止める条件 |

**直し方**: 最初に出した語で最後まで通す。どうしても言い換えるなら、1 度だけ橋を架けて明示する (「操作は、あらかじめ **ツールとして** 実装したものに限定する」)。

**注意**: 平易化のために言い換えたとき、他の節の同じ語とずれることが多い。1 か所直したら、その語を全文検索して揃える。

### 1.2 1 語に 2 つ以上の意味を持たせない

- **症状**: その語が出るたびに解釈が揺れる。対比しているはずの 2 つが同じものに見えて、対比が成立しない
- **原因**: 守備範囲の広い語 (処理、実行、対応、管理、情報、確認) が、文脈ごとに別の意味を吸っている

実例 — 1 文書で「処理」が 4 義:

| 用例 | 意味 |
| --- | --- |
| 用意されていない処理にも対応できる | 個々の操作 |
| 処理状態、処理の管理 | 進行状態 |
| 計画の更新に処理を使う | 計算の手数 |
| 整理する前に処理が止まる | 実行そのもの |

**直し方**: **1 義に絞るのではなく捨てる。** 読者は前に読んだ意味を引きずるので、絞っても残した 1 つが別の意味で読まれる。意味ごとに別の語を割り当てる (操作 / 進行 / 手数 / 実行)。

**検出**: 気になった語を全文検索し、用例ごとに意味を書き出す。2 つ以上に分かれたら該当。

### 1.3 表・コードブロック・見出しで新語を初出させない

- **症状**: 本文で語が突然現れたように見える
- **原因**: 読者が流し読みする場所 (表、図、コードブロック、見出し) が初出だった

実例: フロー図の中で初めて「SRE」が人を指す語として登場し、その後の本文の「SRE へ返す」が唐突に見える。

**直し方**: 人やものを指す具体名は、必ず地の文で 1 度導入してから表や図に出す。

**併せて見る**: 見出しと本文で、同じものを別の動詞で呼んでいないか (見出し「実行できるツール」/ 本文「呼び出せるツール」)。

### 1.4 後付けの注釈が要るなら、語の使い分けが失敗している

- **症状**: 「ここでいう X は〜ではない」という注釈を書きたくなる。読者は「どの X だ」と前を探す
- **原因**: 同じ語を広い意味と狭い意味で使い、区別を使い終わったあとに補っている

**直し方**: 注釈を足すのでも距離を詰めるのでもなく、**最初から語を分ける**。任せる側は「調べ方」、任せない側は「意思決定」と書けば、注釈そのものが不要になる。

**別の現れ方**: 段落が行ったり来たりして前に進まない感じがする。同じ論点を 2〜3 周しているときは、この項を疑う。

## 2. 文の足場

### 2.1 長い目的語・長い列挙で文を始めない

- **症状**: 文を最後まで読まないと何の話か分からない
- **原因**: 文頭が目的語で、しかもその中に「や」「と」でつないだ列挙が入っている

悪い例:

> 参照元や取得時点など事実の出どころと、調査で利用したツールや実行履歴を記録します。

直し方は 2 つある。

- **頭に短い枠か主題を置く** — 「1 回の調査には、〜」「実行経路そのものを、〜」。10 文字前後で足りる
- **述語を先に出して列挙を後ろへ送る** — 「記録するのは、参照元や取得時点といった事実の出どころと、利用したツールや実行履歴です」

日本語は長いものを文末に置くほうが読める。列挙は述語の後ろへ送る。

**注意**: 文末の助詞をいじっても直らない。問題は文頭にある。

### 2.2 太字を打ちたくなったら、文構造を疑う

- **症状**: 一番言いたい語句を太字にしたくなる
- **原因**: その語句が述語から 2 段以上奥にあり、文末を評価語 (「重要です」「必要があります」) が占めている

悪い例:

> 止まったあとに **仕事として成立する結果を残す** ところまで設計することが重要です。

```text
                     ことが重要です   ← 文末（最も強い位置）だが内容はゼロ
              設計する
        ところまで
仕事として成立する結果を残す          ← 一番言いたい語句
```

**直し方**: その語句を述語の位置に出す。出せば強調は不要になる。

> 上限に達しても、調査は安全に止まるだけでなく、仕事として成立する結果を残します。

太字は症状であって原因ではない。太字を外すだけでは読みにくさが残る。

### 2.3 定義は独立した文に切り出す

- **症状**: 中心になる定義なのに、一読で像が結ばない
- **原因**: 次の 2 つが重なっている
  - 修飾が 3 段以上重なっている (「システムから / 明示的に / 委譲された / 範囲内の / 裁量」)
  - 「A を B と定義する」の B に読点入りの長い句を埋め、述語に着くまで解釈を保留させている

**直し方**: 定義は独立文にする。短い文 2 つに割ると、それぞれに主語を書けるので像が結ぶ。

> 調べ方はエージェントが決める。どこまで調べられるかは、あらかじめ仕組みが決める。

### 2.4 定義に当事者を書く

- **症状**: 定義を読んでも、誰が何をするのか分からない
- **原因**: 定義の中身が「2 者の関係」なのに、両者とも文面から消えている。「許された」に許す側がなく、「選べる」に選ぶ側がない

**直し方**: 関係を定義するなら当事者を両方書く。副詞句 (「仕組みとして」) は行為者ではないので、主語の代わりにならない。

## 3. 主語と主題の鎖

### 3.1 否定の直後は同じ主語の肯定で受ける

- **症状**: 「X ではない」と言われたあと、X が何であるかの答えが返ってこない感じがする
- **原因**: 否定文と肯定文で主語が違う

悪い例:

> このエージェントは、人に代わって結論を出す存在ではありません。**人は** ゼロから情報を探すのではなく、整理された判断材料から調査を引き継ぎます。

直した例:

> 〜存在ではありません。人がゼロから情報を探す工程を引き受け、判断材料を整理して渡します。

### 3.2 段落の主題が変わらないなら、途中で主語を替えない

- **症状**: 段落を読み終わって、結局何の話だったかが残らない
- **原因**: 段落の先頭と末尾は A の話なのに、中の文だけ B が主語になっている

**検出**: 段落の各文の主語を書き出す。1 つだけ違うものが混ざっていたらそこ。

### 3.3 主語にしたくない語は連体修飾節に落とす

主語の座を譲りたいが、その語自体は文に残したいときの手。

- 主語のまま: 人がゼロから情報を探すのではなく、〜引き継げるようにする
- 修飾節に落とす: **人がゼロから情報を探す工程** を引き受け、判断材料を整理して渡します

「人」が名詞句の内側に入るので、文の主語は元のまま保たれる。「〜できるようにする」「〜よう」という使役気味の構文が出てきたら、この手で書き直せることが多い。

## 4. 並列するものを揃える

同じ形式で並ぶもの (箇条書き、H2 で並ぶ節、表の行) は、揃っていない 1 つが目に付く。

### 4.1 文種を揃える

- **症状**: 並列した項目のうち 1 つだけ浮いて見える。太字や記号で補強したくなる
- **原因**: 締めの文の種類が混在している

実例: 5 項の締めが「保証 / 保証 / **主張** / 効果 / 保証」。主張 (「〜が重要です」) だけ地の文と種類が違うため、書き手が無意識に太字で補った。

**直し方**: 全項目を同じ種類に書き換える。保証を並べる節なら、主張も効果も保証の形にする。

### 4.2 カテゴリを揃える

- **症状**: 文が最後まで噛み合わない
- **原因**: 「A の 1 つは B」で、A と B のカテゴリが違う

悪い例: 「方法の 1 つに、〜する **構成** があります」(方法 = 行為 / 構成 = 状態)

直した例: 「方法の 1 つは、〜する **こと** です」または「〜を高めるのは、〜する **構成** です」

### 4.3 項目の 1 文目の型を揃える

並ぶ節の 1 文目が、あるものは主題から、あるものは目的語から始まっていると、目的語から始まるものだけ読みづらい (§2.1)。全項目の 1 文目の冒頭を並べて確認する。

### 4.4 要約と本文を対応させる

- **症状**: まとめを読むと、本文で節を立てて書いたものが落ちている。逆に本文に無いものが入っている
- **原因**: まとめを本文と突き合わせずに書いた

**直し方**: まとめの列挙と本文の項目を表で並べ、欠落と過剰を出す。まとめに入る項目の種類も揃える (仕組みが固定する対象と、それが守る結果を混ぜない)。

## 5. 文末とリズム

### 5.1 文末の衝突

- **症状**: 2 文が続けて同じ形で終わり、単調に感じる (「〜ことです。」「〜ことです。」)
- **原因**: 直前の文の文末を見ずに次の文を組んだ

**直す場所は後の文だけではない。** 前の文の文末を変えるほうが、制約が少なく済むことが多い。

> 前文を「〜選べる **点にあります**」に変える → 後文は「方法の 1 つは、〜させる **ことです**」で成立する

後文だけで直そうとすると、カテゴリの一致 (§4.2) と衝突して詰む。レバーが 2 つあることを思い出す。

### 5.2 締めの型を使い回さない

- **症状**: 効かせたい締めが手癖に見える
- **原因**: 同じ修辞 (言い切り + 「これが〜です」、体言止め、対句) を 1 文書で 3 回使っている

**直し方**: 数えて、一番効かせたい 1 か所に残す。ほかは普通の です体に落とす。言い切りは です・ます体に 1 文だけ混ぜると際立つが、2 文続けると演出ではなく書きかけの断片に見える。

## 6. 論理の運び

### 6.1 一段足りない

- **症状**: 結論に飛んだ感じがする。「さらに」を足したくなる
- **原因**: 前提から結論までの中間が 1 つ抜けている

実例: 「候補が複数ある」→「事前に順番を決められない」は飛んでいる。候補が複数あるだけならチェックリスト化できる。抜けているのは「一つ調べた結果によって次に見るべきものが変わる」。

**直し方**: 接続語を足すのではなく、抜けた一段を書く。「さらに」を入れたくなったら、そこに入れるべき文があるということ。

### 6.2 指示語の先を確認する

- **症状**: 「この〜」で一瞬止まる
- **原因**: 指示語の直前の名詞が、指しているはずのものと種類が違う

悪い例: 「安全性と責任の所在は変わりません。**この境界** を保ったまま〜」(安全性は境界ではない)

**直し方**: 指示語をやめて内容語で書く (「境界の引き方を変えずに」)。または直前の名詞を指示対象に揃える。

## 7. 直し方の原則

- **一律ルールに逃げない。** 「全部入れる」「全部外す」はどちらも失敗する。判断の軸 (たとえば「文頭に足場があるか」) を立てたら、軸に従って項目ごとに違う手を打つ。揃えるのは表面の形ではなく、軸を満たしているかどうか
- **症状ではなく原因を直す。** 太字、後付けの注釈、接続語の追加は、たいてい構造の問題への補償である。補償を外すだけでは読みにくさが残る
- **レバーは 1 つではない。** 引っかかっている文だけを見て詰まったら、前の文、見出し、節の順序を動かせないか考える
- **直した箇所の副作用を確認する。** 語を平易化すると別の節と語がずれる。文末を変えると隣の文末と衝突する。1 か所直したら、その語と文末を全文検索する
- **隣接する項目で同じ構文を続けない。** 個別には最善の直し方でも、隣で同じ型を使うと型が透ける
- **重複を「前述のとおり」で処理しない。** 同じことを 2 度書いていて、後のほうが強い主張なら、その段差を見せる。「前述のとおり」は読者に読み飛ばしの許可を出す語なので、強めたい箇所には置かない
