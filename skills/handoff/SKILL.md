# handoff

今の会話から、次のエージェントが**読むだけで状況を把握できる**プロンプトを作る。

## 原則

**引き継ぎ先は文脈を受け取るだけで、次の指示を待つ。**

引き継ぎプロンプトは「続きをやれ」という命令ではない。次のエージェントが作業を始めるかどうかはユーザーが決める。だからプロンプトには「読んで待て」と書き、次の候補は選択肢として示し、出し終えたら自分も何もしない。

## 引数

- `--scope`: 引き継ぐ範囲。省略時は「今のタスクと、それに直接関係するプロジェクト文脈」
  - `task`: 今のタスクのみ
  - `conversation`: 会話全体の要点
  - `debug`: 再現手順・仮説・試したこと・観測結果
  - `review`: レビュー対象・指摘・未解決の議論

## Step 1: 現在の状態を取る

記憶ではなく実物から取る:

```bash
git branch --show-current
git status --short
git log --oneline -10
```

会話中に実行したコマンドとその結果、読んだ / 変更したファイルを思い出し、**確認できる事実**と**推測**に分ける。

## Step 2: 続行に必要なものだけ抽出する

| 項目 | 含めるもの |
|------|-----------|
| 目標 | ユーザーが達成したいこと。言い換えず、ユーザーの言葉に近い形で |
| 環境 | 作業ディレクトリ、ブランチ、ランタイム・ツールのバージョン(確認したものだけ) |
| 指示 | AGENTS.md / CLAUDE.md / ユーザーから受けた制約のうち、今後の行動に効くもの |
| やったこと | 実行したコマンドと重要な結果。読んだ主要ファイル |
| 変更したファイル | パスと変更の要旨。無ければ「なし」 |
| 判断と根拠 | 決めたこと、採らなかった案とその理由 |
| 現状 | どこまで終わり、何が未着手か。ブロッカー |
| 次の候補 | 考えられる次の一手を**選択肢として**。命令形で書かない |
| 注意 | 触ってはいけないもの、壊しやすいもの、安全上の制約 |

含めないもの:

- 謝罪、経過の雑談、途中で捨てた議論の枝
- 内部の推論過程
- secrets・トークン・認証情報・秘密鍵・機微なファイルの中身。**必要なら「どこにあるか」だけを書く**(`.env` に API キーがある、など)

## Step 3: 整える

- 日付・バージョン・パス・コマンド名は具体的に書く
- 不確かな点は「(推測)」「(未確認)」と明示する
- 会話の時系列ではなく、次のエージェントが読む順(目標 → 状態 → 次)に並べ替える

## Step 4: 出力する

次のテンプレートで、**1 つのコードブロック**に入れて出す。出したら止まる。プロンプトに書いた「次の候補」を自分で始めない。

```text
あなたは進行中のタスクの文脈を引き継ぎます。

このプロンプトは文脈を渡すためのものです。ユーザーから次の指示があるまで、ファイルの編集・コマンドの実行・実装の続行はしないでください。

## 目標
- ...

## 環境
- 作業ディレクトリ: ...
- ブランチ: ...
- 関係するプロジェクト指示: ...

## やったこと
- ...

## 変更したファイル
- ...(無ければ「なし」)

## 重要な事実と判断
- ...(推測には「(推測)」と付ける)

## 現状
- ...

## 次の候補(選択肢。実行の指示ではない)
- ...

## 注意
- ...

ユーザーの次の指示を待ってください。
```

## 完了時に返すもの

引き継ぎプロンプトそのもの(コードブロック 1 つ)。前置きの説明や作業報告は付けない。ファイルへの保存を求められた場合だけ、保存先のパスを 1 行添える。
